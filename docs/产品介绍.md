# OpenMeet 产品介绍

> 本地优先的 AI 会议转录工具
> 版本 0.1.0 · MIT 协议 · Windows / macOS / Linux

## 一句话

一款把会议录音变成结构化纪要的桌面应用，**全程在你自己的电脑上完成，不上传任何一个字节**。

## 它解决什么问题

开会记录这件事，现在有三种做法，各有各的难受：

| 做法 | 问题 |
|------|------|
| 人工记录 | 记的人没法参与讨论，会后还要花一小时整理 |
| 在线转录工具 | 录音要上传到别人的服务器，涉密会议根本不敢用 |
| 手机自带转写 | 只有大段文字，分不清谁说的，没有结论和待办 |

OpenMeet 的答案是：**本地跑完整条流水线**。语音识别、说话人分离、纪要生成，全部在本机完成，录音文件不出电脑。适合任何一场"内容不方便交给第三方"的会议——技术方案评审、客户需求沟通、投融资讨论、内部复盘。

## 核心能力

### 转录：三个引擎按场景选

- **Whisper**（faster-whisper）— 英语和多语种表现最好
- **Qwen3-ASR** — 方言和嘈杂环境下最鲁棒
- **Paraformer**（FunASR）— 纯中文场景速度最快

三个引擎都在本地跑。也支持接 OpenAI Whisper API 或阿里云 ASR，但那是可选项，不是必需项。

### 说话人分离：知道每句话是谁说的

CAMPPlus（中文优化）+ pyannote-audio（多语言）双方案，自动切分并标注发言人。配合声纹功能，同一个人在多场会议里可以持续识别。

### 会议纪要：不只是文字堆

接本地 Ollama（Qwen2.5 / Mistral / Llama 任选），自动提炼**议题、结论、待办事项**。纪要里的每一句都能点回原始音频的对应位置。

### 实时转写

WebSocket 流式推送，边录边出字。会开完，初稿也就好了。

### 完整的处理管线

```
音频输入 → 转录 → 说话人分离 → ITN 数字规范化 → 标点恢复 → 生成纪要
```

全自动串起来，中途支持暂停、继续、取消，断了能从断点恢复。

### 其他

- **时间戳定位**：点纪要里的时间戳跳转音频播放，同步高亮
- **项目管理**：文件夹分组，多场会议归档管理
- **多格式导出**：Markdown / JSON / TXT
- **中英双语界面**：完整国际化

## 技术架构

```
┌─────────────────────────────────────┐
│  Tauri 桌面应用                       │
│  ┌────────────┐   ┌──────────────┐  │
│  │ React 19   │   │ Rust Core    │  │
│  │ TypeScript │←→ │ 音频采集/调度  │  │
│  └────────────┘   └──────┬───────┘  │
└──────────────────────────┼──────────┘
                           │ Sidecar
                  ┌────────▼─────────┐
                  │ Python FastAPI   │
                  │ ASR / 分离 / LLM  │
                  └────────┬─────────┘
                           │
                  ┌────────▼─────────┐
                  │ SQLite 本地存储   │
                  └──────────────────┘
```

| 层级 | 技术选型 |
|------|----------|
| 桌面框架 | Tauri 2.x（Rust） |
| 前端 | React 19 + TypeScript + Vite + Radix UI + TailwindCSS |
| 状态管理 | Zustand |
| 后端服务 | Python 3.12 + FastAPI（以 Sidecar 形式随应用启停） |
| ASR 引擎 | faster-whisper / Qwen3-ASR / FunASR Paraformer |
| 说话人分离 | CAMPPlus + pyannote-audio |
| 纪要生成 | Ollama 本地 LLM |
| 数据库 | SQLite |
| 音频处理 | FFmpeg + cpal |

**为什么用 Tauri 而不是 Electron**：安装包体积小一个数量级，内存占用低，而 ASR 本身就吃内存，省下来的都是刀刃上的。

**为什么 Python 服务做成 Sidecar**：ASR 生态在 Python，但用户不该被要求装 Python 环境。Sidecar 随应用启动和退出，用户无感。

## 和其他方案的区别

| | OpenMeet | 在线转录 SaaS | 手机自带转写 |
|---|---|---|---|
| 数据出本机 | 不出 | 全量上传 | 多数上传 |
| 说话人分离 | 有 | 部分有 | 基本没有 |
| 结构化纪要 | 议题/结论/待办 | 部分有 | 没有 |
| 引擎可选 | 三选一 | 固定 | 固定 |
| 长期成本 | 一次性 | 按分钟计费 | 免费但能力有限 |
| 离线可用 | 可以 | 不行 | 部分 |

## 适合谁

- **有保密要求的团队**：技术方案、客户信息、财务数据不能进第三方服务器
- **会议密集的管理者**：一天四五个会，需要快速拿到结论和待办
- **多方言环境**：Qwen3-ASR 在带口音的普通话上明显更稳
- **需要长期归档的组织**：本地 SQLite，数据是自己的，不受服务商存续影响

## 当前状态

版本 0.1.0，核心链路全部跑通：多引擎转录、说话人分离、声纹匹配、本地知识库嵌入、纪要生成、导出、自动更新。

已具备发布条件（含 release workflow 和 auto-updater）。
